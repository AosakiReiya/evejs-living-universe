# Development scripts and workflow

## `xeve-patch` (Go CLI)

The repository is a Go module. Build and test with the `Makefile`:

```bash
make build       # host build -> dist/xeve-patch
make test        # go test ./...
make vet         # go vet ./...
make audit       # validate the release package (manifest + overlay integrity)
make build-all   # cross-compile linux/darwin/windows, amd64/arm64 -> dist/
make release     # cross-compile + package release zips -> dist/
```

Version is a single source of truth in `VERSION`, injected at build time:

```bash
go build -ldflags "-X .../internal/buildinfo.Version=$(cat VERSION)" ./cmd/xeve-patch
```

## Regenerating the release manifest

`patches/manifest.json` is generated, not hand-edited. It describes every file
in the overlay trees with its baseline and installed hashes:

```bash
make manifest
```

This runs `xeve-patch manifest generate --baseline tmp/EveJS-v0.12.3.1`. The
`--baseline` argument must point at a **clean, unmodified** EveJS v0.12.3.1
tree. Baseline hashes come from that tree; installed hashes come from
`patches/files/` (main overlay) and `patches/docker-overlay/`.

## Regenerating the module index

`patches/modules.json` is a pure-metadata index that assigns every overlay file
to a subsystem. It is generated by the Go CLI itself:

```bash
make modules        # xeve-patch modules generate
```

The classifier lives in `internal/modules/classify.go`: curated prefix rules
classify every manifest file, and generation fails if any file is unassigned or
assigned twice. `xeve-patch audit` (included in `make check`) validates the
index against the manifest and the config gates.

`make manifest` regenerates the index and the manifest together, stamping each
file with its module (manifest schema v3). Adding a new file to the mod
requires classifying it in `internal/modules/classify.go` first.

## Local testing

`tmp/` is a local, untracked working directory. Put a clean upstream EveJS
baseline here for local install/verify testing:

```powershell
mkdir tmp
# Extract the clean EveJS archive into tmp/EveJS-v0.12.3.1
```

Then exercise the full lifecycle against that tree:

```bash
make build
./dist/xeve-patch status tmp/EveJS-v0.12.3.1
./dist/xeve-patch install tmp/EveJS-v0.12.3.1
./dist/xeve-patch verify tmp/EveJS-v0.12.3.1
./dist/xeve-patch uninstall tmp/EveJS-v0.12.3.1
```

`tmp/` is never committed. `git clean -fdX tmp` removes it.
